# 首次使用检查

检查日期：2026-09-22。

结论：安装、项目绑定、登记和查询服务器、独立 Skill、网页和 VS Code 的主要上手路径已走通。检查发现的引导缺失和误导性反馈已修复。以下是本次实际验证范围，不代表所有平台或所有集群都已验证。

## 发现与修复

| 原有体验 | 本次处理 |
| --- | --- |
| 未构建网页时，`serve` 仍给出 URL，打开后才遇到 404 | 启动前检查资源，返回 `web_assets_missing`，直接给出构建和重新安装步骤。 |
| 构建前安装 CLI，之后仅执行 `uv tool install --force .` 可能继续使用旧缓存 | 经隔离安装复现后，将更新命令改为 `uv tool install --reinstall .`；保留直接调用仓库脚本的方式。 |
| 多个项目占用同一网页端口时，只有底层系统错误 | 返回 `port_in_use`，提示 `serve --port 0` 自动选空闲端口。 |
| VS Code 未初始化项目只有错误文字 | 活动栏提供可点击的初始化入口；打开工作台也会引导初始化，并绑定所选项目。 |
| SSH 探测失败仍显示“操作完成” | 显示“连接失败”、SSH 原因与排查建议，保留最近一次有效数据。 |
| 远程命令失败时，具体输出藏在原始 JSON 中 | 直接展示 stdout、stderr 和退出码；结果不确定时提示先查询原生状态。 |
| 同步预览和真实传输都叫“操作完成” | 预览明确显示“尚未传输文件”。 |
| 保存成功后再次点击可能新增重复记录或重复执行 | 修改操作成功后禁用重复提交；修改参数或重开表单后恢复。 |
| CLI 将连接异常显示成过期，中文名称使表格错位 | 区分 `connection_failed` 与 `stale`，按中文字符显示宽度对齐。 |
| 网页令牌失效时还展示“添加第一台服务器” | 显示连接恢复提示，提供令牌输入，禁用不可用的新增入口。 |

README 补充了 Python 虚拟环境安装方式、命令找不到时的处理、首次 SSH 认证，以及不需要真实服务器的示例台账路径。详细排障见 [使用指南](usage.md#首次使用排障)。

## 验证证据

- **干净安装**：将版本库文件放入独立临时目录，隔离 uv 的工具和可执行文件目录；确认原始代码无需网页构建即可安装 CLI 和复制独立 Skill，复制后的 Skill 能在仓库外运行。
- **README 路径**：项目初始化、服务器登记、查询、示例台账导入、JSON 导出及重新导入另一个项目均通过；包含空格的本地项目目录正常工作。
- **构建与安装**：干净目录执行 `npm ci`、`npm run build`；随后 `uv tool install --reinstall`。安装后的 CLI 用随机空闲端口启动网页，HTML 及其引用资源均可访问，令牌保护的 API 返回正确项目及 3 台示例服务器。
- **Python**：42 项测试通过，包括真实回环 SSH、特殊字符参数/路径、补丁冲突、rsync 预览和传输、原生 tmux、项目隔离、HTTP 校验，以及新增的启动引导和状态展示回归。
- **前端**：5 项结果展示测试通过，覆盖连接失败、命令错误输出、不确定结果、同步预览与缓存状态；TypeScript、Vite 和扩展构建通过。
- **浏览器实际操作**：空台账、新增服务器、JSON 连接参数、连接失败、重复保存保护、编辑参数后恢复提交、搜索无匹配与清除筛选、无令牌访问与重新认证均通过。420px 宽窗口下详情及错误可读，页面无水平溢出。正常登录页未出现控制台错误。
- **真实 VS Code 宿主**：扩展激活、Webview RPC、两个项目的同名服务器隔离通过；第三个新项目可通过初始化命令直接打开可用工作台。测试使用一次性的已信任配置，日常编辑器配置不受影响。
- **发布包**：重新生成 Skill ZIP、wheel 和 VSIX，并逐字节核对其中的 Python 模块及前端资源与当前源码/构建一致。
